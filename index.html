00 · CONTEXT

先把论文问题说清楚。

ReFocus 不是单独提出一个更大的视觉语言模型，而是把“用户会继续纠正模型”这个现实场景加入 episodic memory 检索。

01

原来的 NLQ 是一次性检索

给模型一段长的第一视角视频和一个自然语言问题，模型直接输出一个时间窗口。这个设置默认问题足够明确，也默认第一次预测不会错。

现实中用户往往只记得一部分信息，例如只知道“那个蓝色的杯子”，或者看到模型给出错误片段后才想起来“应该在这之前”。

02

EM-QnF 把纠错变成正式任务

用户先提问，模型先预测，然后用户提供反馈，模型重新定位。反馈可以包含新增信息、否定信息和相对时间信息，并且可以继续多轮发生。

因此评测对象从“一次预测是否正确”扩展为“模型能否利用反馈修正预测”。

03

ReFocus 的贡献是轻量适配

FALM 作为 plug-and-play 模块读取视频、原始 query 和 feedback，产生每个 clip 的 alignment score，再用轻量 EM Adapter 调整原有 EM-NLQ 模型的特征。

核心卖点是不用把基础模型从头训练，也不要求每一轮反馈都做昂贵的 sequential optimization。

02B · DATA STRUCTURE

拿到数据后，实际看到的是什么？

原始视频和原始 benchmark 需要单独获取；EM-QnF 仓库主要提供反馈标注 JSONL、预提取的视觉与文本特征，以及评测 checkpoint。

字段含义为什么需要
video_id视频或 clip 标识把反馈和原始视频对齐
query_id唯一 annotation UID区分同一个问题的不同反馈实例
query_type如 nlq_feedback区分普通 NLQ 与反馈任务
query原始自然语言问题描述用户想找什么
feedback用户纠正文字告诉模型当前预测哪里不对
timestamps真实片段 [start, end]训练和评测的 ground truth
pred_timestamp之前的错误预测明确反馈是在纠正哪一次结果
clip_span / durationclip 在完整视频中的范围与长度把相对时间换回长视频坐标

02C · FEEDBACK RECIPE

标注生成 pipeline 需要特别说明。

这些反馈不是简单把 ground truth 时间戳翻译成一句话，而是围绕“模型为什么错、用户会怎样纠正”来构造。

STEP 1

采样 reference span

从原始 NLQ 样本中拿到正确的时间段，作为最终应该被检索到的 reference。

STEP 2

生成片段描述

使用 LVLM 为候选片段和参考片段生成 caption，抽取人物、物体、动作、场景和顺序信息。

STEP 3

解释预测差异

描述初始预测与 ground truth 的区别，例如物体颜色错了、动作错了、场景错了，或时间方向错了。

STEP 4

生成多样反馈

用 LLM 生成更接近人类表达的反馈，并覆盖 contains、not-contains 和 temporal 三类信息。

为什么不全部人工标注？长视频逐条观看和多轮反馈标注成本很高。作者采用可扩展的 synthetic feedback recipe，再用 human-generated feedback 做泛化验证。汇报时可以把它解释为“自动扩充规模，人工检验真实感”。

04B · MODEL

FALM 在模型里具体做什么？

它的定位不是替代原有 temporal grounding 模型，而是把反馈信息转换成可以作用于视频 clip 的对齐权重。

Video encoder每个 clip 的视觉特征
+
Query encoder原始问题语义
+
Feedback encoder纠正与补充线索
→
Alignment score P每个 clip 与 feedback 的匹配程度

Transformer encoder-decoder：融合视频、query 和 feedback，预测 per-clip alignment score。

EM Adapter：通过两个可学习标量把 FALM 分数注入现有 EM-NLQ 模型，不需要重写基础架构。

Multi-turn：不同轮次的反馈分数采用 late fusion，累积多轮纠正信息。

05 · PIPELINE

从原始视频到反馈对齐。

数据生成和模型推理是两条相互衔接的链路：先把已有 NLQ 变成 EM-QnF，再用 FALM 把反馈转成片段级权重。

01

原始数据

Ego4D-NLQ / GoalStep / HD-EPIC 提供视频、问题和真实时间段。

video + query + ground truth span
02

构造反馈

采样参考片段，用 LVLM 生成描述，再由 LLM 生成内容、排除和时间反馈。

query + wrong prediction + feedback
03

FALM 对齐

编码视频、问题和反馈，计算每个 clip 的 alignment score，重加权原模型特征。

clip score P → EM Adapter
04

评测反馈后的定位

输出新的时间段，用 Recall@K 和 IoU 衡量是否找回正确事件。

prediction → R@K / IoU

06 · REPRODUCIBILITY

如果要复现实验，实际要准备什么？

汇报时可以把“公开了什么”和“仍然需要申请什么”分开讲，避免把 annotation 仓库误认为完整视频数据集。

01

获取原始数据权限

Ego4D、Ego4D-GoalStep、HD-EPIC 的视频和原始 NLQ 数据不包含在这个 GitHub 仓库里，需要遵守各自的访问和许可条款。

02

准备 JSONL 与 LMDB

把对应 split 的 JSONL 放入 data 目录，并下载项目提供的 subset LMDB。README 给出了 ego4d_qnf val、goalstep_qnf test、hd_epic_qnf test 的特征包。

03

下载 checkpoint

使用 refocus_emqnf.t7，并按照 GroundNLQ 的配置启动 eval_jsonl.py。项目当前 README 说明 training code 将后续发布。

04

运行统一评测

在仓库根目录执行 bash run_eval.sh，预测结果和日志写入 results/eval/，再按 R@1、R@3、R@5 和 IoU 阈值比较。

07 · PRESENTATION NOTES

汇报时可以怎么讲？

下面这段话可以直接作为 1 分钟说明，也可以继续展开成数据、方法、实验三页。

“这项工作研究的是长时第一视角视频里的交互式事件定位。已有 NLQ 方法通常只做一次预测，但真实用户会在模型答错后补充线索。作者因此提出 EM-QnF，把原始 Ego4D-NLQ、GoalStep 和 HD-EPIC 转成带反馈的数据集；每条样本同时记录原问题、用户反馈、正确时间段和模型之前的错误预测。ReFocus 里的 FALM 负责计算反馈与每个视频 clip 的对齐分数，再轻量地调整原模型的注意力。最后用 Recall@K 和 IoU 评估模型是否通过反馈找回正确片段。”

对方问：视频是原始视频吗？

答：是第一视角生活记录，但 ReFocus 仓库本身主要发布反馈标注、特征和评测代码，原始视频要通过三个来源数据集获取。

对方问：反馈是真人写的吗？

答：主要采用 synthetic feedback generation 扩展规模，同时用人类反馈做泛化验证。它不是传统的纯人工逐条标注。

对方问：有没有 leaderboard？

答：当前项目给出固定 split 的结果和复现脚本，没有看到独立在线 leaderboard。公平比较要锁定测试集和指标定义。

对方问：它和视频问答有什么区别？

答：输出重点不是自然语言答案，而是视频中的时间区间。反馈的作用是重新定位 temporal span。
